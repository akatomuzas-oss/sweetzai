# sweetzai.com Landing Site

Static landing page deployed as a **separate Vercel project**. Zero dependency on the main `sweetz.ai` app. Its only job:

1. Show two video cards (Realistic / Anime). A **single coinflip per page load** picks missionary OR blowjob globally — both cards show the same pose (never mixed).
2. On click, redirect to `https://sweetz.ai/create?style=<realistic|anime>&variation=<missionary|blowjob>&<...tracking params>`

The main app wizard at `sweetz.ai/create` already reads `?style=` and skips the style-picker step (verified in `src/app/(main)/create/page.tsx:1014`), so the handoff is seamless.

## Current media state

The landing currently uses **animated WebP** files generated by the WAN 2.2 I2V
pipeline in `../landing-video/`. WebP plays natively in every modern browser
(Safari 14+, Chrome 32+, Firefox 65+) with no `<video>` element required — they
just render as `<img>` tags and autoloop forever. This is simpler than the
video path and ships today with the assets we already have.

If you later generate proper webm/mp4 variants (smaller, hardware-decoded),
drop them into `public/videos/` and swap `MEDIA_EXT`/`MEDIA_BASE` in
`script.js` to use the `<video>` path instead.

## How to deploy

### Option A — Brand new Vercel project (recommended)

1. Create a new git repo just for this folder (or leave it nested in the monorepo — Vercel supports a project rootDirectory of `marketing-assets/landing-site`)
2. In Vercel dashboard: **Add New Project** → import repo → set "Root Directory" to `marketing-assets/landing-site`
3. **Framework Preset:** Other (static)
4. **Build Command:** leave empty
5. **Output Directory:** leave empty (or set to `.` — there's no build step)
6. **Domains:** attach `sweetzai.com` + `www.sweetzai.com` in project settings
7. Deploy

### Option B — From this monorepo without splitting

1. In Vercel, **Add New Project** → import the same git repo that hosts the main sweetz app
2. Create a **second** project in Vercel that uses the same repo
3. Set **Root Directory:** `marketing-assets/landing-site`
4. Attach `sweetzai.com` to this project
5. The main `sweetz.ai` Vercel project stays untouched

Either way, the main app's Vercel project is unaffected. Two projects, two domains, one repo or two — your call.

## How the coinflip works

On every page load, `script.js` runs `pickVariation()` **once** and applies the result to both cards. So a visitor always sees a **coherent** set — either:

| Coinflip result | Realistic card | Anime card |
|---|---|---|
| `missionary` | `realistic_missionary` | `anime_missionary` |
| `blowjob` | `realistic_blowjob` | `anime_blowjob` |

Never mixed (e.g. realistic missionary + anime blowjob) — that would look incoherent.

The chosen variation is:

1. **Set as the `<video>` source on both cards** — user only downloads 2 videos per visit (one per card), not all 4
2. **Forwarded as a URL param** (`?variation=...`) into the main app on click, so attribution can track which pose the user converted on
3. **Sent in a `landing_view` analytics event** so you know which variation was shown even if the user bounces

This gives you:
- **Perceived variety** — returning visitors and shared links see a different pose
- **Free A/B data on pose** — after ~500 visitors you'll know if missionary or blowjob converts better as a landing hook
- **Visual coherence** — every visit shows one "theme," not a jarring mismatch

## Attribution

Every URL param from the inbound ad is forwarded across the domain hop. The list in `script.js`:

```
ref, utm_source, utm_medium, utm_campaign, utm_content, utm_term,
fpr, fbclid, twclid, gclid, rdt_cid
```

Then `script.js` appends `style` and `variation` and redirects. So a Reddit ad hitting `sweetzai.com/?utm_source=reddit&utm_campaign=launch_v1` becomes:

```
sweetz.ai/create?utm_source=reddit&utm_campaign=launch_v1&style=realistic&variation=blowjob
```

The main app should capture `utm_source`, `variation`, and `style` on `/create` page mount and persist them to localStorage for later conversion attribution.

## Analytics endpoint (optional)

`script.js` fires two `navigator.sendBeacon` events to `https://sweetz.ai/api/landing-event`:

1. **`landing_view`** — on page load, with the coinflip results and referrer
2. **`style_click`** — on card click, with the chosen style and variation

If that endpoint doesn't exist yet, the calls silently fail (wrapped in try/catch). Create a thin endpoint in the main app later if/when you want landing-side funnel data — it's optional.

## Rotation

When you want to refresh landing assets:

1. Run the `landing-video/` workflow again with new prompts or new cherry-picks
2. Replace the 8 files in `public/videos/`
3. Redeploy (Vercel auto-deploys on push, or click Redeploy in dashboard)

Cache headers are `max-age=31536000, immutable` on `/videos/*`, so **rename the new files** if you want users to see them immediately — e.g. `realistic_missionary_v2.webm` — and update the constant in `script.js`. Otherwise users keep the cached old file for up to a year.

Simpler pattern: change the `VIDEO_BASE` constant in `script.js` to include a version (`/videos/v2/`) and drop new files under that subdirectory.

## Why this is separate from the main app

- **Compliance firewall.** Segpay and payment processors review `sweetz.ai`, not `sweetzai.com`. This landing can be as explicit as needed without risking the main domain's reputation.
- **Ad account survivability.** If Reddit/X flag `sweetzai.com`, you spin up `sweetzgirls.com` → deploy the same folder → re-point DNS. The main app is untouched.
- **Build cost.** Main Vercel project costs ~$1/build. This project is static HTML — effectively free to redeploy. You can iterate landing videos daily without burning Vercel credits.
- **Independent uptime.** If the main app has an issue, landing still serves. Ad traffic doesn't bounce on an outage.
